# llamaUI — 使用说明

> English version: [USAGE.md](USAGE.md) · 项目介绍: [../README.zh-CN.md](../README.zh-CN.md)

本文按界面顺序说明每个功能。所有路径示例均为占位符，请以你自己机器为准。

---

## 1. 首次运行

1. 把 `llamaui.exe` 放到你放 `llama.cpp` 的目录，或随便一个目录。
2. 双击运行。程序不会弹出控制台窗口。
3. 启动时会自动找 `llama-server.exe`，搜索顺序：
   1. 配置里的「llama-server 路径」（如果填了且文件存在）
   2. 程序目录、程序目录的上级目录（最多向上 4 层）
   3. 上述目录下的**任意子目录**（因此 `llama-b12549\`、`llama-b13000\` 这类带版本号的目录都能认）
   4. 上述目录下的 `bin\` 子目录
   5. 系统 `PATH`
4. 找不到时，日志第一行会写：

   > 未发现 llama-server：可到「高级设置 → llama-server 路径」点「浏览…」指定其他位置，
   > 或自行下载 llama.cpp 的 Windows 版本后把 llama-server.exe 放到程序目录（或子目录）

5. 找到时日志会写一行 `llama-server: <完整路径>`，并解析它的 `--help` 建立参数表。

## 2. 模型库（左侧）

### 导入与扫描

| 操作 | 说明 |
|---|---|
| **导入文件夹** | 选一个目录，递归（最多 4 层、最多 4000 个文件）扫描其中所有 `.gguf`；同时把这个目录**登记进扫描目录列表** |
| **扫描目录** | 对扫描列表里的所有目录做一次同步 |

扫描是**双向同步**，日志会写清楚结果：

```
scan finished: +2 added, -1 removed, 3 updated (total 10)
  removed: 某个已删除的模型
```

- `+N added`：新增的模型文件
- `-M removed`：文件已经不存在，条目被移除（如果它所在的**父目录也打不开**，例如移动硬盘拔了，
  则保留条目，避免误删）
- `K updated`：文件大小、同目录的 `mmproj`、识图标记或原生上下文有变化

`mmproj*.gguf` 不会被当成独立模型，而是作为同目录模型的视觉投影文件。

### 列表里的标记

- ✅ **复选框图标**：该模型检测到视觉投影文件，属于识图模型
- **红色文字**：当前 llama.cpp 构建不支持该模型的架构（日志里会有
  `unknown model architecture: 'xxx'`），换一个能支持该架构的 llama.cpp 版本才行，改设置无用
- 名字太长时会在原位滚动显示

### 右键菜单

- **打开所在目录**：在资源管理器中定位并选中该 `.gguf`
- **从模型库移除**：只从库中移除，不删除磁盘文件

## 3. 常用设置（右侧）

| 字段 | 说明 |
|---|---|
| **模型别名** | 接口里调用的模型名。留空则用文件名。建议填短名字，智能体框架里好写 |
| **上下文长度 (tokens)** | 通常是模型的原生上限，从 GGUF 头自动填入。客户端（尤其智能体框架）常要求 ≥ 67000。改小会省显存 |
| **上下文跟随模型** | 勾选后切换模型时自动改成该模型的原生上下文（超过 262144 时封顶）。取消勾选则完全用你手填的值 |
| **GPU 层数** | 99 表示尽量全部放到 GPU；显存不够就调小，剩下的层跑在 CPU 上 |
| **CPU 线程数** | 生成阶段线程数，0 = 自动 |
| **并发槽位** | 同时处理几个请求，1 = 串行 |
| **Flash Attention** | `auto` / `on` / `off`，长上下文时开启可省显存 |
| **推理引擎** | `llama.cpp` / `KVMem` / `NInfer`。启动时探测本机实际装了哪些，**没装的不会出现在下拉框里** |
| **开启识图** | 勾选后启动参数会带上 `--mmproj`。切换模型时按该模型是否有视觉投影文件自动同步 |
| **启用 Jinja 模板** | 建议勾选，否则工具调用、思考模式可能不生效 |
| **允许局域网访问** | 勾选后监听 `0.0.0.0`，顶部地址会变成局域网 IP，可一键复制给别的设备 |
| **启用 API 密钥校验** | 勾选后请求必须带 `Authorization: Bearer <密钥>` |
| **自定义绑定地址 / 服务端口** | 默认 `127.0.0.1` / `9931` |
| **API 密钥列表** | 可多条，取第一条。右侧「复制」「生成新密钥」 |

填写中的提示行会显示上下文来源（自动跟随模型上限 / 手动指定）与识图状态。

**保存设置** 会把当前表单写回 `data/config.json`。

## 4. 启动、停止与日志

- **启动服务**：按当前配置拼参数，启动 `llama-server`，日志实时出现在右下窗格
- **停止服务**：结束子进程
- 切换模型时，如果服务正在运行，**不会**自动停掉；界面会提示当前跑的仍是上一个模型，
  需要手动点「停止服务」后再启动（避免打断正在进行的对话）
- **清空日志**：只清界面，不动文件

顶部状态栏显示：运行状态、当前模型、**本次运行累计 token 用量（输入/输出）**、运行时长。
token 用量是解析 llama-server 自己的计时日志累加的，所以**任何客户端**（面板聊天、你的智能体直连）
的调用都计入；每次启动服务时归零。

---

### 数据监控

点顶部 **数据监控** 打开独立窗口，实时显示这一次运行的状况（关掉窗口即停止采集，不影响服务）：

- **显卡**：利用率、显存占用、温度、功耗（走 NVML，驱动不支持时显示「不可用」）
- **实时 · 输入**：当前阶段、本次输入 token、输入速度、KV 缓存命中
- **实时 · 生成**：已生成 token、输出速度、剩余 token、上下文峰值
- **请求历史**：每个已完成请求的输入/输出 token、预填充与生成速度、耗时、MTP 接受率

数据来自 `GET /slots`、`GET /props` 和运行日志，因此**任何客户端**（面板聊天、你的智能体、curl）发的请求都会被统计。
写「—」表示当前取不到（未启用、本机驱动不提供，或服务没在运行）。


## 5. 启动参数预览 与 参数解读

左下「启动参数预览」显示即将传给 `llama-server` 的完整命令行（密钥会打码）。

点右上 **参数解读**，会打开一个新窗口，把参数逐条拆开：

```
* -c 32768
   上下文窗口大小（token 数）。需要容纳提示词 + 历史 + 生成内容；智能体框架通常要 67000 以上。
   EN: size of the prompt context (default: 0 = loaded from model)
```

- 已有中文解读的参数，显示中文 + 官方英文原文
- 没有中文的，显示「（自动解析自当前 llama-server --help）」+ 英文原文 + 默认值/可选值
- 内容较长时可滚动查看

### 生成中文解读

点窗口下方 **生成中文解读**：

1. 只处理"当前启动参数里、还没有中文说明"的参数
2. 用你**本地正在运行的 llama-server** 来翻译（走 `/completion` 接口，绕开思考模式）
3. 结果写入 `locales/params.zh-CN.json`，按英文说明的哈希缓存 —— llama.cpp 只改了文案才会重译
4. 后台线程执行，不卡界面；完成后自动刷新窗口

想人工修订：直接编辑该文件，把条目的 `by` 改成 `"human"`，程序**永远**不会覆盖它。

## 6. 自动发现的新参数

高级设置底部有「自动发现的新参数 N」和「设置…」按钮。点开是一个分页表单：

- 列出当前 llama-server 有、但本程序还没建模的参数（例如 `--chat-template-kwargs`）
- 控件类型自动推断：无值参数 → 勾选框；有可选值 → 下拉；其余 → 文本框
- 顶部有**筛选框**，按参数名或英文说明模糊匹配（例如输入 `cors`、`template`）
- 填好后「保存并关闭」，值落到 `config.auto.<参数名>`，并自动附加到启动参数
- 留空表示不使用该参数

程序认识的参数（会手写中文说明的那些）不会出现在这个窗口里。

## 7. 聊天页

点 **打开测试聊天** 会用默认浏览器打开 `http://127.0.0.1:<面板端口>/chat.html`。

- 面板端口与 `llama-server` 端口不同，面板默认 `8790`（见 `data/config.json` 的 `panel.port`）
- 聊天页把消息代理到 `llama-server` 的 `/v1/chat/completions`，自动带上 API 密钥
- 支持图片：点图片按钮选择文件、直接粘贴、或拖拽进输入框（仅识图模型）
- 长边超过 1568 像素的图片会自动缩小
- 模型不支持图片时会提示，不会静默失败

## 8. 高级设置

点顶部 **高级设置** 打开（窗口较大，可拖动）。字段分三列。

### 生成参数

`识图投影文件 (mmproj)`、`加载模式`、`多卡切分方式`、`显存分配比例`、`主 GPU 序号`、
`MoE 保留 CPU 层数`、`KV 缓存 K/V 类型`、`批处理大小`、`微批大小`、`温度`、`Top-K`、
`Top-P`、`Min-P`、`重复惩罚`、`随机种子`、`读写超时`、`HTTP 线程数`

### 开关

`启用 llama 自带聊天界面`、`启用监控指标`、`暴露槽位接口`、`仅嵌入模式`、`跳过预热`、
`新版本自动生成中文解读`

`新版本自动生成中文解读` 默认关闭。打开后：当检测到 llama-server 换了版本、
且服务正在运行并且**空闲**（`/slots` 显示没有正在处理的请求）时，自动跑一次翻译，
每个版本只跑一次（版本哈希记录在 `app.autoTranslatedFor`）。

### 文本

`推理思考模式`、`思考预算 (tokens)`、`输出上限 (tokens)`、`进程优先级`、`NUMA 策略`、
`自定义聊天模板文件`、`CORS 允许来源`、`附加命令行参数`

### RoPE 缩放

当上下文超过模型训练时长时，位置编码会被迫外推，输出质量明显下降（llama.cpp 只给一条
`possible training context overflow` 警告，并不阻止启动）。这一组用来代替裸外推：

| 字段 | 说明 |
|---|---|
| **RoPE 缩放方式** | `自动` / `不缩放` / `线性 (linear)` / `YaRN`。选「自动」则完全交给引擎按 GGUF 元数据决定 |
| **RoPE 扩展倍率** | 0 = 自动按「上下文 ÷ 模型原生上下文」计算 |
| **YaRN 原始上下文** | 0 = 用模型自带训练上下文；仅 YaRN 方式会用到 |

`附加命令行参数` 是终极逃生口：任何本程序不认识的参数都可以直接写在这里，按空格分词，
支持双引号包住含空格的值。

### llama-server 路径

留空则自动识别；也可点右侧 **浏览…** 手动指定 `.exe`。

### 模型扫描目录

一个列表：

- 相对路径（如 `models`、`llama-b12549`）= **程序自带**，后面标注「（程序自带）」，**不可删除**
- 绝对路径 = 你自己添加的目录（通过主页「导入文件夹」加入），**右键可移除**
- 程序目录下**任何包含 `llama-server.exe` 的子目录**都会自动出现在列表里，
  所以换 llama.cpp 版本、目录名变了也能识别

## 9. 配置文件

| 文件 | 内容 |
|---|---|
| `data/config.json` | 全部设置、API 密钥、扫描目录、llama-server 路径 |
| `data/models.json` | 模型库（路径、大小、原生上下文、mmproj、标记） |
| `data/param-cache.json` | 参数表缓存（按 exe 大小+修改时间失效，可安全删除） |
| `locales/params.zh-CN.json` | 参数中文解读缓存（可手改，`by` 改 `human` 即锁定） |
| `logs/` | 服务日志（若启用） |

删掉 `data/` 等于恢复出厂设置（模型库和密钥都会丢，请注意备份）。

## 10. 常见问题

**启动后立刻退出 / 日志里 `unknown model architecture`**
当前 llama.cpp 构建不支持这个模型的架构。换新版 llama.cpp，或换模型。这类问题改任何设置都无效。

**客户端报上下文太小（例如 `4096 tokens` 之类的错误）**
调大「上下文长度」。智能体框架常要求 67000 以上。注意还要有足够显存/内存。

**发图片报 `image input is not supported`**
该模型没有视觉投影文件。用识图模型，或别发图。「开启识图」只对确实带 `mmproj` 的模型生效。

**端口被占用**
启动时会自动结束占用该端口的进程并记日志；也可以自己改端口。

**换了 llama.cpp 版本后参数报错**
程序会在启动前剔除"本程序认识但新版已删除"的参数并记日志。
若日志出现 `xxx 不在当前 llama-server 参数表中`，说明该参数来自「附加命令行参数」，
去高级设置里删掉它即可。

**局域网设备连不上**
确认勾选了「允许局域网访问」；检查 Windows 防火墙是否放行 `llama-server.exe` 与面板端口。
