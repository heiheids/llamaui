llamaUI 1.2.0 发布说明
======================================================================

版本：1.2.0（llamaui.exe 文件版本 1.2.0.0）
日期：2026-11-25
引擎：llama.cpp（本版验证 b12675，Windows x64 CUDA 构建）
作者：黑山大叔

  https://github.com/heiheids

----------------------------------------------------------------------
本版重点：把「显存怎么分配」交给 llama.cpp 自己算

之前显存估算是本程序用 GGUF 元数据推的，遇到滑窗、混合注意力、自定义
注意力的新架构偏差很大（gemma 高估一倍多，Inkling 低估 5 GB）。本版接入
llama.cpp b126xx 新增的 --fit 拟合，并由实测数据持续校正。

1. 自动适配显存（--fit）
   - 设置项移到 Flash Attention 右侧，默认开启
   - 开启后不再传 -c / -ngl，由 llama.cpp 按可用显存自己决定层数和上下文
   - 实测（RTX 2080 Ti 22 GB，Inkling-2-Mini）：自动定到 339200 上下文，
     占用 21.3/22.5 GB，生成 27.4 tok/s
   - 配套参数：显存余量（--fitt，默认 1024 MiB）、拟合最小上下文（--fitc）

2. 提示词缓存
   - 上下文检查点（-ctxcp，默认 32）
   - 提示词缓存上限（-cram，默认 8192 MiB）
   - 缓存复用块大小（--cache-reuse）
   - 实测：同一段 3223 token 提示，首次 16.46 s，重复 2.68 s
   - 注意：带视觉投影（mmproj）时 llama.cpp 会禁用 --cache-reuse

3. 上下文按模型记忆
   - 每个模型单独记住自己的上下文，互不影响
   - 没设置过 → 默认 65536（64K），避免不看设置直接启动就爆显存
   - 手动填过的值会被记住
   - 「上下文跟随模型」勾选 = 用该模型原生上限（封顶 262144）

4. 显存估算与实测校准
   - 每次启动都会记录一个「上下文 → 实测占用」采样点，按模型累积
   - 两个点以上时直接用实测直线外推，绕开所有结构假设
   - 没实测过的模型不再给数字和推荐，只提示先启动一次（滑窗模型按公式
     估算偏差太大，给错数字比不给更糟）
   - 显存占用 ≥98.5%（真正换页）时丢弃样本，并在日志说明原因

5. 加载模式与 MoE
   - 加载模式新增 dio（--load-mode）
   - MoE 专家显存缓存（--moe-cache-mib）

----------------------------------------------------------------------
修复

- 保存设置时界面卡死：自写函数在已持有共享锁的情况下再次加锁，触发
  std::sync::Mutex 非重入死锁
- 参数表解析漏掉「说明写在下一行」的参数，参数表从 222 条补到 267 条
  （-fitt 就在其中，导致它被当成已删除参数）
- 过滤已删除参数时把值留在命令行里，形成游离位置参数，llama-server 直接
  启动失败（表现为「-fit on 1024」）
- 滑窗模型 KV 被按全注意力估算，导致严重高估（gemma 64K 算成 35 GB）
- 校准的溢出保护阈值过严（92%），把 94% 正常运行的状态误判为换页，
  导致部分模型永远校准不上

----------------------------------------------------------------------
已知限制

- 首字延迟取决于预填充速度，与上下文大小关系不大。同一段 8022 token 提示：
    b2048/ub512 → 21.1 s（22.0 GB）
    b1024/ub256 → 24.6 s（19.4 GB）
    b256/ub64   → 34.6 s（14.6 GB）
  小批大小是为了塞下超大上下文，≤128K 时建议 1024/256 或 2048/512
- 提示词缓存命中时同一请求只要 0.8 s；客户端若每轮改写前缀，则每次都付
  全额预填充
- 逐层滑窗模式（sliding_window_pattern）的 0/1 语义无公开文档，这类模型的
  KV 体积只能靠实测确认
- Unsloth 的 Inkling 根目录文件是自定义布局（inkling2），mainline
  llama.cpp 读不了，需使用 Mainline_Support/ 目录下的文件并改名为 .gguf

----------------------------------------------------------------------
安装与运行

1. 解压到任意目录（路径不要有中文以外的特殊字符问题）
2. 把 llama.cpp 的 llama-server.exe 所在目录放在与本程序同级，或在
   「llama 下载」里让程序自己管理
3. 运行 llamaui.exe
4. 首次使用先「导入文件夹」把模型目录加进来，再选模型 → 启动服务

数据保存在程序目录的 data\ 下（配置、模型库、实测校准），可整体迁移。
